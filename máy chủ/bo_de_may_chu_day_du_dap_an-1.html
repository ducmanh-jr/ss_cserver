BỘ 1

Câu 1

Chỉ ra đoạn code xử lý API lấy danh sách phòng từ database và trả về cho client. Nếu muốn bổ sung trường isAvailable vào response JSON thì em sửa ở Controller hay Service? Giải thích.

Đáp án

API lấy danh sách thường nằm ở Controller, ví dụ:

@GetMapping("/rooms")
public ResponseEntity<List<RoomResponse>> getAllRooms() {
    List<RoomResponse> rooms = roomService.getAllRooms();
    return ResponseEntity.ok(rooms);
}

Luồng xử lý:

Client gọi GET /rooms
→ RoomController nhận request
→ RoomService xử lý nghiệp vụ
→ RoomRepository lấy dữ liệu từ database
→ Service map Entity sang Response DTO
→ Controller trả JSON về client

Nếu thêm trường isAvailable, nên sửa ở DTO/Response và Service, không nên xử lý trực tiếp ở Controller.

public class RoomResponse {
    private Long id;
    private String name;
    private Double price;
    private Boolean isAvailable;
}
RoomResponse response = new RoomResponse();
response.setId(room.getId());
response.setName(room.getName());
response.setPrice(room.getPrice());
response.setIsAvailable(room.getStatus().equals("AVAILABLE"));

Controller chỉ nhận request và trả response. Service chịu trách nhiệm xử lý logic dữ liệu.

Câu 2

Mở hàm xử lý API thêm mới phòng. Dữ liệu từ request body được lấy như thế nào trước khi ghi xuống database? Thử đổi trường pricePerNight thành price và chỉ ra tất cả vị trí phải đồng bộ.

Đáp án

Dữ liệu được lấy từ request body thông qua @RequestBody.

@PostMapping("/rooms")
public ResponseEntity<RoomResponse> createRoom(@RequestBody RoomRequest request) {
    RoomResponse result = roomService.createRoom(request);
    return ResponseEntity.status(HttpStatus.CREATED).body(result);
}

DTO nhận dữ liệu:

public class RoomRequest {
    private String name;
    private Double pricePerNight;
    private Integer capacity;
}

Khi đổi pricePerNight thành price, cần sửa đồng bộ ở:

Vị tríCần sửa
FrontendBody gửi lên API
Request DTOpricePerNight → price
Servicerequest.getPricePerNight() → request.getPrice()
EntityNếu Entity cũng dùng tên cũ thì đổi theo
DatabaseNếu tên cột là price_per_night thì cân nhắc đổi hoặc map bằng annotation

Ví dụ sau khi sửa:

public class RoomRequest {
    private String name;
    private Double price;
    private Integer capacity;
}
room.setPrice(request.getPrice());

Câu 3

Sau khi xóa phòng thành công, API đang trả về mã trạng thái HTTP nào? Nếu muốn trả về thêm thông báo {"message":"Delete success"} thì sửa đoạn nào?

Đáp án

API xóa thường dùng DELETE và trả về 204 No Content hoặc 200 OK.

@DeleteMapping("/rooms/{id}")
public ResponseEntity<Void> deleteRoom(@PathVariable Long id) {
    roomService.deleteRoom(id);
    return ResponseEntity.noContent().build();
}

Đoạn trên trả về 204 No Content, không có body.

Nếu muốn trả thông báo thì sửa Controller:

@DeleteMapping("/rooms/{id}")
public ResponseEntity<Map<String, String>> deleteRoom(@PathVariable Long id) {
    roomService.deleteRoom(id);
    Map<String, String> response = new HashMap<>();
    response.put("message", "Delete success");
    return ResponseEntity.ok(response);
}

Khi đó HTTP status là 200 OK.

Câu 2

Giải thích logic validate dữ liệu trước khi thêm mới. Bây giờ thêm điều kiện: Giá phòng phải lớn hơn 0. Em sẽ sửa ở đâu?

Đáp án

Validate nên đặt trong DTO bằng annotation hoặc trong Service.

Cách tốt nhất với Spring Boot là dùng Bean Validation:

public class RoomRequest {
    @NotBlank(message = "Tên phòng không được bỏ trống")
    private String name;

    @NotNull(message = "Giá phòng không được bỏ trống")
    @Positive(message = "Giá phòng phải lớn hơn 0")
    private Double price;
}

Controller cần thêm @Valid:

@PostMapping("/rooms")
public ResponseEntity<RoomResponse> createRoom(@Valid @RequestBody RoomRequest request) {
    return ResponseEntity.status(HttpStatus.CREATED).body(roomService.createRoom(request));
}

Nếu không dùng annotation, có thể validate trong Service:

if (request.getPrice() == null || request.getPrice() <= 0) {
    throw new IllegalArgumentException("Giá phòng phải lớn hơn 0");
}

Câu 3

Đề bài yêu cầu không cho cập nhật mã phòng. Em đang khóa dữ liệu ở DTO, Entity, Controller hay SQL Query? Hãy chỉ ra đoạn code.

public class UpdateRoomRequest {

public RoomResponse updateRoom(Long id, UpdateRoomRequest request) {

Câu 2

Đoạn code nào chịu trách nhiệm mapping dữ liệu RoomDTO ⇄ RoomEntity? Hãy giải thích.

Đáp án

Mapping thường nằm trong Service hoặc Mapper riêng.

private RoomResponse mapToResponse(Room room) {
    RoomResponse response = new RoomResponse();
    response.setId(room.getId());
    response.setName(room.getName());
    response.setPrice(room.getPrice());
    response.setCapacity(room.getCapacity());
    return response;
}

Mapping từ Request DTO sang Entity:

private Room mapToEntity(RoomRequest request) {
    Room room = new Room();
    room.setName(request.getName());
    room.setPrice(request.getPrice());
    room.setCapacity(request.getCapacity());
    return room;
}

DTO dùng để giao tiếp với client. Entity dùng để ánh xạ với database. Không nên trả trực tiếp Entity ra client.

Câu 3

Nếu client gửi thiếu trường price, server xử lý thế nào? Response thực tế là gì?

Đáp án

public class RoomRequest {
    @NotBlank(message = "Tên phòng không được bỏ trống")
    private String name;

    @NotNull(message = "Giá phòng không được bỏ trống")

@PostMapping("/rooms")

Khi thiếu price, server trả 400 Bad Request.

{
  "price": "Giá phòng không được bỏ trống"
}

Cần có handler:

@ExceptionHandler(MethodArgumentNotValidException.class)
public ResponseEntity<Map<String, String>> handleValidation(MethodArgumentNotValidException ex) {
    Map<String, String> errors = new HashMap<>();
    ex.getBindingResult().getFieldErrors().forEach(error -> {
        errors.put(error.getField(), error.getDefaultMessage());
    });
    return ResponseEntity.badRequest().body(errors);
}

Câu 2

Giải thích ý nghĩa LIMIT và OFFSET trong API phân trang. Nếu muốn lấy 20 bản ghi mỗi trang thì sửa ở đâu?

Đáp án

LIMIT là số bản ghi cần lấy. OFFSET là số bản ghi cần bỏ qua.

SELECT * FROM rooms LIMIT 10 OFFSET 20;

Nghĩa là bỏ qua 20 bản ghi đầu, lấy 10 bản ghi tiếp theo.

Nếu muốn lấy 20 bản ghi mỗi trang, sửa default size:

@RequestParam(defaultValue = "20") int size

Hoặc khi gọi API:

GET /rooms?page=0&size=20

Câu 3

Nếu API trả dữ liệu quá chậm, em sẽ kiểm tra SQL Query, Index Database, Network, Logic Service theo thứ tự nào? Giải thích.

Đáp án

Thứ tự kiểm tra hợp lý:

1. Log thời gian request ở server
2. SQL Query
3. Index Database
4. Logic Service
5. Network / Frontend

Giải thích:

  • Nếu query chậm, cần kiểm tra câu SQL và dùng EXPLAIN.
  • Nếu lọc theo cột không có index, database sẽ quét toàn bảng.
  • Nếu Service xử lý vòng lặp quá nhiều hoặc gọi API phụ nhiều lần thì cũng chậm.
  • Nếu server xử lý nhanh nhưng client nhận chậm thì mới kiểm tra network/frontend.

Ví dụ thêm index:

CREATE INDEX idx_rooms_price ON rooms(price);

BỘ 6

Câu 1

API đăng nhập đang xác thực tài khoản bằng cách nào: so sánh trực tiếp mật khẩu, hash password hay JWT? Mở code chứng minh.

Đáp án

Đăng nhập đúng chuẩn là kiểm tra mật khẩu đã hash, sau đó sinh JWT.

@PostMapping("/login")
public ResponseEntity<LoginResponse> login(@RequestBody LoginRequest request) {
    return ResponseEntity.ok(authService.login(request));
}
public LoginResponse login(LoginRequest request) {
    User user = userRepository.findByEmail(request.getEmail())
        .orElseThrow(() -> new RuntimeException("Email không tồn tại"));

    if (!passwordEncoder.matches(request.getPassword(), user.getPassword())) {
        throw new RuntimeException("Sai mật khẩu");
    }

    String token = jwtUtil.generateToken(user.getEmail());
    return new LoginResponse(token);
}

Dòng chứng minh dùng hash password:

passwordEncoder.matches(request.getPassword(), user.getPassword())

Dòng chứng minh dùng JWT:

jwtUtil.generateToken(user.getEmail())

Câu 2

Sau khi đăng nhập thành công, token được tạo ở đâu? Hãy chỉ ra JwtUtil hoặc jwt.encode hoặc jsonwebtoken.sign.

Đáp án

Với Spring Boot, token thường tạo trong class JwtUtil:

public String generateToken(String email) {
    return Jwts.builder()
        .setSubject(email)
        .setIssuedAt(new Date())
        .setExpiration(new Date(System.currentTimeMillis() + 86400000))
        .signWith(SignatureAlgorithm.HS256, secretKey)
        .compact();
}

Service gọi:

String token = jwtUtil.generateToken(user.getEmail());

Token được trả về client:

{
  "token": "eyJhbGciOiJIUzI1NiJ9..."
}

Câu 3

Nếu token hết hạn, Server trả về 401 hay 403? Giải thích.

Đáp án

Token hết hạn nên trả về 401 Unauthorized.

  • 401: Chưa xác thực, token sai, token hết hạn.
  • 403: Đã xác thực nhưng không có quyền truy cập.

Ví dụ trong filter:

try {
    String email = jwtUtil.extractEmail(token);
} catch (ExpiredJwtException e) {
    response.setStatus(HttpServletResponse.SC_UNAUTHORIZED);
    response.getWriter().write("Token expired");
    return;
}

Câu 3

Nếu người dùng upload file 100MB thì hệ thống xử lý ra sao? Giới hạn dung lượng được cấu hình ở đâu?

Đáp án

Giới hạn upload thường nằm trong application.properties:

spring.servlet.multipart.max-file-size=10MB
spring.servlet.multipart.max-request-size=10MB

Nếu upload file 100MB, server trả lỗi do vượt quá dung lượng, thường là 413 Payload Too Large hoặc 500 nếu chưa xử lý lỗi.

Nên bắt lỗi:

@ExceptionHandler(MaxUploadSizeExceededException.class)
public ResponseEntity<Map<String, String>> handleMaxSizeException() {
    Map<String, String> response = new HashMap<>();
    response.put("message", "File vượt quá dung lượng cho phép");
    return ResponseEntity.status(HttpStatus.PAYLOAD_TOO_LARGE).body(response);
}

Chỉ ra toàn bộ luồng xử lý của API POST /rooms từ lúc client gửi request tới khi dữ liệu được lưu thành công vào database.

Nếu thêm sản phẩm mà thiếu tên, server đang bắt lỗi ở đâu? Hãy sửa để trả về thông báo "Tên sản phẩm không được bỏ trống".

Đáp án

exports.createProduct = async (req, res) => {
  const { name, price } = req.body;

  if (!name || name.trim() === '') {
    return res.status(400).json({
      message: 'Tên sản phẩm không được bỏ trống'
    });
  }

  const product = await Product.create({ name, price });
  res.status(201).json(product);
};

Lỗi được bắt ở Controller hoặc Middleware validate.

Câu 1

Trong FastAPI, API thêm mới dữ liệu nhận body bằng model nào? Chỉ ra đoạn code.

Đáp án

@app.post("/rooms")
def create_room(room: RoomCreate, db: Session = Depends(get_db)):

Câu 2

Nếu muốn validate giá phòng phải lớn hơn 0 trong FastAPI thì sửa ở đâu?

Đáp án

Sửa trong Pydantic model:

from pydantic import BaseModel, Field

class RoomCreate(BaseModel):
    name: str
    price: float = Field(gt=0, description="Giá phòng phải lớn hơn 0")
    capacity: int

Nếu client gửi price <= 0, FastAPI tự trả lỗi 422 Unprocessable Entity.

Câu 3

Khi database không tìm thấy phòng theo ID, API nên trả lỗi gì? Viết code.

Đáp án

Nên trả 404 Not Found.

from fastapi import HTTPException

@app.get("/rooms/{room_id}")
def get_room(room_id: int, db: Session = Depends(get_db)):
    room = db.query(Room).filter(Room.id == room_id).first()

    if room is None:
        raise HTTPException(status_code=404, detail="Room not found")

    return room

Response:

{
  "detail": "Room not found"
}

TÓM TẮT MẪU TRẢ LỜI KHI THI

Khi gặp câu hỏi kiểu này, nên trả lời theo công thức:

1. Chỉ ra file / class / hàm nằm ở đâu
2. Đọc đúng dòng code chính
3. Giải thích luồng dữ liệu
4. Nếu đề yêu cầu sửa, nêu rõ sửa file nào
5. Nếu có lỗi, nêu HTTP status và response trả về

Ví dụ mẫu:

API này nằm trong RoomController, hàm getAllRooms().
Controller nhận request GET /rooms rồi gọi roomService.getAllRooms().
Service gọi roomRepository.findAll() để lấy dữ liệu từ database.
Sau đó Service map Entity sang DTO và Controller trả về ResponseEntity.ok().
Nếu muốn thêm trường mới thì sửa Entity, DTO, Service mapping và frontend body nếu có.
